Specifications & build scope

ZBOM: every target component is freshly generated from capsule-owned source. Native execution uses Linux x86-64 syscalls directly. Source records and verification results accompany each build.

Native compiler self-hosting, three-stage byte comparisons, ELF64 object generation, native static linking, separately compiled modules and automated regression supervision are operational.

Every executable is ELF64 for x86-64, with 8-byte pointers. Required narrow ELF fields, byte strings and syscall buffers retain their specified widths. The dialect uses 8-byte plain int, 1-byte char and 4-byte explicit signed/unsigned int; narrow loads and returns zero-extend.

The compiler supports functions, recursion, six register arguments, grouped object declarations, globals, pointers, fixed arrays, strings, casts, sizeof, conditional and assignment expressions, sequenced comma expressions, loops, switch dispatch and short-circuit logic. Full preprocessing, structs/unions, floating point, variadic or indirect calls, stack arguments, archives and dynamic linking remain outside the supported profile.

vxiv verification record

The native chain passed 424 positive fixtures and 245 source-rejection fixtures. The verifier runs 67,107 in-memory checks. Injected statuses 2, 3, 64 and 70 halted the build before consumption; regression-child failures propagated to the main chain. The embedded native sources match the tested sources.

The browser download flow and installer generation were not re-executed during this native-only integration pass. ELF structure checks do not attest source provenance. The current RWX executable layout remains explicit.
